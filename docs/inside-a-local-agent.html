Inside a local agent

One real session with Inkling 2 Mini on a 16 GB MacBook Air M2, recorded by a single-file Python harness and replayed here: text becomes token IDs, token IDs come back one sample at a time, and a tool call is just text that the server parses and the harness executes.

01Install the model

Everything lives in ~/Workspaces/inkling-2-mini. Nothing is installed system-wide, so a broken global OpenCode or Ollama doesn't matter.

1
./scripts/download-model.sh

Looks up unsloth/Inkling-2-Mini-GGUF on Hugging Face, downloads UD-Q2_K_XL (9.14 GB) with resume support, and compares its SHA-256 with the LFS hash the Hub reports. GGUF is a single file holding the quantized weights, the tokenizer vocabulary and the Jinja chat template.

2
sudo sysctl iogpu.wired_limit_mb=12288

macOS lets Metal wire only about two-thirds of unified memory by default (≈10.7 GiB on 16 GiB). Raising the cap to 12 GiB makes room for weights plus KV cache. It resets on reboot; start-server.sh does this for you.

3
./scripts/start-server.sh

Runs Unsloth's llama.cpp build b12588-mix-c0c3de8, which knows Inkling's looped layer layout. Mainline builds at launch did not.

4
python3 harness/mvp_agent.py

The harness behind every number on this page. It writes harness/trace.json, which you can drop into the sidebar loader to replay a new run.

Where the 16 GiB goes

Weights 8.51 GiB
KV + buffers ≤ 3.49
macOS + apps 4
UD-Q2_K_XL file: 9.14 GB = 8.51 GiB left inside the 12 GiB GPU cap outside the cap

A mixture-of-experts model reads only ~3.4B of its 26.4B parameters per token, but all 26.4B must be resident, because the router picks different experts for every token. Speed scales with active parameters; memory scales with total parameters.

02The server

llama-server is the inference engine and the HTTP API in one process. Every agent you put in front of it, OpenCode or the harness, is just an HTTP client.

FlagWhy it's set
--jinjaRender prompts with the chat template embedded in the GGUF. Without it, tool schemas and tool-call parsing don't work.
--ctx-size 16384KV-cache capacity in tokens. OpenCode's system prompt plus tool definitions use roughly 10k tokens before you type anything.
--n-gpu-layers 99Put every layer on Metal. Partial offload on unified memory saves nothing and runs slower.
--cache-type-k/v q8_0Store the KV cache in 8-bit, roughly halving it versus f16. Needs flash attention.
--parallel 1One slot. Each slot reserves its own share of the context window.
--temp 1.0 --top-p 1.0 --top-k 0 --min-p 0Unsloth's recommended sampling: draw from the model's full, unmodified distribution.

Endpoints the harness calls

EndpointUsed for
GET /propsModel path, context size, build, and the raw Jinja chat template.
POST /tokenize, /detokenizeText ↔ token IDs with with_pieces, so you can see each piece.
POST /apply-templateMessages + tool schemas → the exact string the model reads. No generation happens.
POST /completionRaw text in, raw tokens out, with n_probs: 5. Nothing is parsed.
POST /v1/chat/completionsOpenAI-compatible streaming. The server templates the prompt, then splits the output into reasoning_content, content and tool_calls. This is what OpenCode uses.

Read from GET /props and GET /v1/models during the recorded run.

03Words become token IDs

The model never sees characters. The tokenizer, a byte-level BPE vocabulary stored inside the GGUF, greedily merges bytes into the longest known pieces and emits integer IDs. Common English words are one token; rare words, numbers and non-Latin scripts split into several. A leading space is usually part of the token, so "hello" and " hello" get different IDs.

Each row below came from POST /tokenize on your machine and was round-tripped through /detokenize. The small number under each piece is its ID.

· marks a space, ↵ a newline. Token count matters for cost: context, KV-cache memory and prefill time all scale with tokens, not characters.

04The chat template: what the model actually reads

"Messages" and "tools" are an API fiction. Before generation, the server runs the GGUF's Jinja template and flattens the system prompt, the JSON schema of every tool and the user's question into one long string with special marker tokens between turns. The model was trained on exactly this format, so the template is part of the model.

This is the turn-1 prompt from the recorded run, returned by /apply-template. Highlighted pieces are control markers. Switch to the token view and click any token to see its ID.

Two details to look for in Inkling's template. Tool schemas go in first, as compact JSON inside a tool_declare system message. And the template inserts its own system line, Thinking effort level: 0.9, unless the request passes chat_template_kwargs: {"reasoning_effort": "low"}. That one number controls how many thinking tokens you pay for on every turn.

05Tokens come back one sample at a time

Generation has two phases. Prefill pushes the whole prompt through the network in parallel and fills the KV cache; it's compute-bound and fast per token. Decode then produces one token per forward pass: the network outputs a probability for every entry in the vocabulary, the sampler draws one, and that token is appended and fed back in. Decode is bound by memory bandwidth, because every step must read the active weights, which is why an M2's ~100 GB/s sets the pace.

Press play to replay a recorded stream at its real timing. There are two recordings. Turn 1, raw came from /completion and carries the top-5 candidates for every token; highlighted tokens are control markers the API normally hides. Click any token to see what else the sampler could have chosen; a wavy underline means the chosen token had under 50% probability. Agent loop came from /v1/chat/completions, colored by role: purple thinking, green answer, amber tool call. llama-server won't return probabilities for a streamed request with tools, so that view has timing but no sampler data.

07The agent loop

      

        
An agent is a while loop around a stateless function. The model keeps no memory between requests: every turn, the harness resends the entire message list, now including the tool calls and results so far. The server's prefix cache (cache_n below) is what keeps that from re-running prefill over the whole history each time.

4 · Serverparses into tool_calls

08The harness code

      

        
The whole agent fits in one standard-library file. The parts that matter for understanding OpenCode, Claude Code or any other agent are the stream accumulator, the tool dispatcher and the guardrails. The rest is logging for this page.

      

      

        
The loop, condensed


messages = [system, user]
for step in range(MAX_STEPS):              # guardrail 1
    msg = stream(POST /v1/chat/completions,
                 messages, tools=SCHEMAS)
    if not msg.tool_calls:
        return msg.content                 # done
    messages.append(msg)                   # model's call
    for call in msg.tool_calls:
        if call in seen: block()           # guardrail 2
        args = json.loads(call.arguments)  # may fail

        messages.append({"role": "tool",
            "tool_call_id": call.id,
            "content": out})

Tool calls arrive in fragments, like text. The first delta for index 0 carries id and name; later deltas carry slices of the arguments JSON string. The harness concatenates by index and parses only after finish_reason: "tool_calls". Parsing early is a classic bug.

#!/usr/bin/env python3
"""
MVP agent harness for a local llama-server (Inkling 2 Mini).

Standard library only. It does what OpenCode does, minus the UI:
  1. Render the conversation + tool schemas into the model's raw prompt (chat template)
  2. Tokenize that prompt
  3. Stream tokens back, with the top-5 alternatives the sampler chose from
  4. Detect tool calls, execute them locally, append results, and loop
Everything is recorded to harness/trace.json so the explainer page can replay it.

Usage (server must be running on 127.0.0.1:8080):
  python3 harness/mvp_agent.py
  python3 harness/mvp_agent.py --task "your own question"
"""
import argparse, ast, json, operator, os, sys, time, urllib.error, urllib.request

BASE = os.environ.get("LLAMA_URL", "http://127.0.0.1:8080")
ROOT = os.path.abspath(os.path.join(os.path.dirname(__file__), ".."))   # tools may only touch this folder
OUT = os.path.join(os.path.dirname(os.path.abspath(__file__)), "trace.json")

DEFAULT_TASK = ("Which quant does scripts/download-model.sh download by default? "
                "Then use the calculator to convert 9140000000 bytes to GiB, rounded to 2 decimals. "
                "Use the tools; do not guess.")

# Guardrails: the HN thread reported a runaway loop of 180+ tool calls. Real harnesses cap everything.
MAX_STEPS = 6            # model turns per task
MAX_TOKENS = 1536        # generated tokens per turn (thinking + answer)
WALL_CLOCK_S = 900       # whole task

# ---------------------------------------------------------------- HTTP helpers
def post(path, body, timeout=600):
    req = urllib.request.Request(BASE + path, data=json.dumps(body).encode(),
                                 headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(req, timeout=timeout) as r:
        return json.loads(r.read())

def get(path):
    with urllib.request.urlopen(BASE + path, timeout=30) as r:
        return json.loads(r.read())

def sse(path, body):
    """Yield parsed JSON events from a server-sent-events stream."""
    req = urllib.request.Request(BASE + path, data=json.dumps(body).encode(),
                                 headers={"Content-Type": "application/json"})
    try:
        r = urllib.request.urlopen(req, timeout=900)
    except urllib.error.HTTPError as e:
        raise RuntimeError(f"{path} -> HTTP {e.code}: {e.read().decode('utf-8', 'replace')[:500]}") from None
    with r:
        for raw in r:
            line = raw.decode("utf-8", "replace").strip()
            if not line.startswith("data:"):
                continue
            data = line[5:].strip()
            if data == "[DONE]":
                return
            try:
                yield json.loads(data)
            except json.JSONDecodeError:
                continue

def piece_text(p):
    return p if isinstance(p, str) else bytes(p).decode("utf-8", "replace")

def tokenize(text, add_special=False):
    r = post("/tokenize", {"content": text, "add_special": add_special, "with_pieces": True})
    return [{"id": t["id"], "piece": piece_text(t["piece"])} if isinstance(t, dict) else {"id": t, "piece": None}
            for t in r["tokens"]]

# ---------------------------------------------------------------- tools
def _safe(path):
    full = os.path.abspath(os.path.join(ROOT, path))
    if not full.startswith(ROOT):
        raise ValueError("path escapes the project folder")
    return full

def list_files(path="."):
    full = _safe(path)
    return sorted(n + ("/" if os.path.isdir(os.path.join(full, n)) else "") for n in os.listdir(full)
                  if not n.startswith("."))[:200]

def read_file(path, max_chars=4000):
    with open(_safe(path), "r", errors="replace") as f:
        return f.read()[: int(max_chars)]

_OPS = {ast.Add: operator.add, ast.Sub: operator.sub, ast.Mult: operator.mul, ast.Div: operator.truediv,
        ast.Pow: operator.pow, ast.USub: operator.neg, ast.FloorDiv: operator.floordiv, ast.Mod: operator.mod}

def calculate(expression):
    def ev(n):
        if isinstance(n, ast.Constant) and isinstance(n.value, (int, float)): return n.value
        if isinstance(n, ast.BinOp) and type(n.op) in _OPS: return _OPS[type(n.op)](ev(n.left), ev(n.right))
        if isinstance(n, ast.UnaryOp) and type(n.op) in _OPS: return _OPS[type(n.op)](ev(n.operand))
        if isinstance(n, ast.Call) and getattr(n.func, "id", "") == "round": return round(*[ev(a) for a in n.args])
        raise ValueError("only arithmetic is allowed")
    return ev(ast.parse(expression, mode="eval").body)

TOOLS = {"list_files": list_files, "read_file": read_file, "calculate": calculate}
TOOL_SCHEMAS = [
    {"type": "function", "function": {"name": "list_files", "description": "List files in a folder of the project.",
        "parameters": {"type": "object", "properties": {"path": {"type": "string", "description": "Folder, relative to project root"}}}}},
    {"type": "function", "function": {"name": "read_file", "description": "Read a text file from the project.",
        "parameters": {"type": "object", "properties": {"path": {"type": "string"}}, "required": ["path"]}}},
    {"type": "function", "function": {"name": "calculate", "description": "Evaluate an arithmetic expression, e.g. round(9140000000/1024**3, 2).",
        "parameters": {"type": "object", "properties": {"expression": {"type": "string"}}, "required": ["expression"]}}},
]

# ---------------------------------------------------------------- model turn
def model_turn(messages, step_rec):
    """Stream one assistant turn through the OpenAI-compatible endpoint (what OpenCode uses).
    llama-server rejects logprobs together with tools + stream, so token probabilities
    come from the raw /completion capture instead; here each SSE chunk is ~one token."""
    body = {"model": "inkling-2-mini", "messages": messages, "tools": TOOL_SCHEMAS, "stream": True,
            "max_tokens": MAX_TOKENS,
            "temperature": 1.0, "top_p": 1.0, "top_k": 0, "min_p": 0.0,
            "timings_per_token": True}
    content, reasoning, calls, tokens = "", "", {}, []
    t0 = time.time(); first = None; finish = None; timings = {}
    for ev in sse("/v1/chat/completions", body):
        if ev.get("timings"): timings = ev["timings"]
        ch = (ev.get("choices") or [{}])[0]
        d = ch.get("delta", {}) or {}
        now = round(time.time() - t0, 3)
        kind = None
        if d.get("reasoning_content"): reasoning += d["reasoning_content"]; kind = "reasoning"
        if d.get("content"): content += d["content"]; kind = "content"
        for tc in d.get("tool_calls") or []:
            c = calls.setdefault(tc.get("index", 0), {"id": None, "name": "", "arguments": ""})
            if tc.get("id"): c["id"] = tc["id"]
            fn = tc.get("function") or {}
            c["name"] += fn.get("name") or ""
            c["arguments"] += fn.get("arguments") or ""
            kind = "tool_call"
        for lp in ((ch.get("logprobs") or {}).get("content") or []):
            if first is None: first = now
            tokens.append({"t": now, "kind": kind or "content", "token": lp.get("token"),
                           "logprob": round(lp.get("logprob", 0), 4),
                           "top": [{"token": a.get("token"), "logprob": round(a.get("logprob", 0), 4)}
                                   for a in lp.get("top_logprobs", [])]})
        if kind and not ch.get("logprobs"):
            frag = d.get("reasoning_content") or d.get("content") or "".join(
                ((tc.get("function") or {}).get("name") or "") + ((tc.get("function") or {}).get("arguments") or "")
                for tc in d.get("tool_calls") or [])
            tokens.append({"t": now, "kind": kind, "token": frag, "logprob": None, "top": []})
        if ch.get("finish_reason"): finish = ch["finish_reason"]
        sys.stdout.write("." if kind == "reasoning" else (d.get("content") or ("" if kind != "tool_call" else "*")))
        sys.stdout.flush()
    print()
    step_rec.update({"reasoning": reasoning, "content": content, "finish_reason": finish,
                     "tool_calls": [calls[i] for i in sorted(calls)], "tokens": tokens,
                     "ttft_s": first, "duration_s": round(time.time() - t0, 2), "timings": timings})
    return step_rec

# ---------------------------------------------------------------- main
def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--task", default=DEFAULT_TASK)
    ap.add_argument("--no-raw", action="store_true", help="skip the raw /completion capture (saves time)")
    args = ap.parse_args()
    trace = {"created": time.strftime("%Y-%m-%dT%H:%M:%S%z"), "base_url": BASE, "task": args.task,
             "limits": {"max_steps": MAX_STEPS, "max_tokens": MAX_TOKENS, "wall_clock_s": WALL_CLOCK_S}}

    print("== 1. Server properties")
    props = get("/props")
    trace["props"] = {k: props.get(k) for k in ("model_path", "build_info", "total_slots", "modalities", "model_alias")}
    dgs = props.get("default_generation_settings", {}) or {}
    trace["props"]["n_ctx"] = dgs.get("n_ctx") or props.get("n_ctx")
    trace["props"]["chat_template_head"] = (props.get("chat_template") or "")[:6000]
    try: trace["models"] = get("/v1/models")
    except Exception as e: trace["models"] = {"error": str(e)}
    print(json.dumps({k: trace["props"][k] for k in ("model_path", "n_ctx", "build_info")}, indent=1))

    print("== 2. Tokenizer samples")
    samples = ["Hello world", "Hello, world!", " hello", "tokenization", "Optiver market maker",
               "9140000000 bytes", "def fib(n):\n    return n", "Sydney 悉尼 🦘", "antidisestablishmentarianism"]
    trace["tokenizer"] = []
    for s in samples:
        toks = tokenize(s)
        back = post("/detokenize", {"tokens": [t["id"] for t in toks]}).get("content")
        trace["tokenizer"].append({"text": s, "tokens": toks, "roundtrip": back})
        print(f"{s!r:40} -> {len(toks)} tokens {[t['piece'] for t in toks]}")

    messages = [{"role": "system", "content": "You are a concise assistant working inside a local project folder. "
                 "Use tools to inspect files and do arithmetic. Answer in one or two sentences."},
                {"role": "user", "content": args.task}]

    print("== 3. Chat template: what the model really sees")
    try:
        rendered = post("/apply-template", {"messages": messages, "tools": TOOL_SCHEMAS})["prompt"]
    except Exception as e:
        rendered = f"(apply-template failed: {e})"
    ptoks = tokenize(rendered, add_special=True)
    trace["template"] = {"messages": json.loads(json.dumps(messages)), "tools": TOOL_SCHEMAS, "prompt": rendered,
                         "prompt_tokens": ptoks}
    print(f"rendered prompt: {len(rendered)} chars, {len(ptoks)} tokens")

    if not args.no_raw:
        print("== 4. Raw generation for turn 1 (before the server parses tool calls)")
        raw = {"tokens": [], "text": ""}
        t0 = time.time()
        for ev in sse("/completion", {"prompt": rendered, "n_predict": 768, "stream": True, "n_probs": 5,
                                      "return_tokens": True, "temperature": 1.0, "top_p": 1.0, "top_k": 0,
                                      "min_p": 0.0, "cache_prompt": True}):
            probs = ev.get("completion_probabilities") or []
            ids = ev.get("tokens") or []
            for i, p in enumerate(probs or [{}]):
                if not ev.get("content") and not p: continue
                raw["tokens"].append({"t": round(time.time() - t0, 3), "id": p.get("id", ids[i] if i < len(ids) else None),
                                      "token": p.get("token", ev.get("content")),
                                      "logprob": round(p["logprob"], 4) if "logprob" in p else None,
                                      "top": [{"id": a.get("id"), "token": a.get("token"),
                                               "logprob": round(a.get("logprob", 0), 4)}
                                              for a in (p.get("top_logprobs") or p.get("probs") or [])]})
            raw["text"] += ev.get("content") or ""
            if ev.get("stop"):
                raw["timings"] = ev.get("timings"); raw["stop_type"] = ev.get("stop_type")
                raw["stopping_word"] = ev.get("stopping_word")
            sys.stdout.write(ev.get("content") or ""); sys.stdout.flush()
        print()
        # /completion hides special tokens in its text. Detokenizing each ID reveals the hidden
        # control markers (turn boundaries, tool-call delimiters) the parser looks for.
        for t in raw["tokens"]:
            if t["id"] is not None:
                try: t["piece"] = post("/detokenize", {"tokens": [t["id"]]}).get("content", "")
                except Exception: t["piece"] = None
        hidden = [t for t in raw["tokens"] if t.get("piece") and not t.get("token")]
        print(f"   {len(raw['tokens'])} tokens, {len(hidden)} control tokens hidden from the text: "
              f"{sorted(set(t['piece'] for t in hidden))[:10]}")
        trace["raw_turn1"] = raw

    print("== 5. Agent loop")
    trace["steps"] = []
    start, seen = time.time(), set()
    for step in range(1, MAX_STEPS + 1):
        if time.time() - start > WALL_CLOCK_S:
            trace["stopped"] = "wall clock limit"; break
        print(f"-- turn {step}: model is generating")
        rec = model_turn(messages, {"step": step, "context_messages": len(messages)})
        trace["steps"].append(rec)
        if not rec["tool_calls"]:
            trace["final_answer"] = rec["content"]; trace["stopped"] = "model answered"; break
        messages.append({"role": "assistant", "content": rec["content"] or "",
                         "tool_calls": [{"id": c["id"] or f"call_{step}_{i}", "type": "function",
                                         "function": {"name": c["name"], "arguments": c["arguments"]}}
                                        for i, c in enumerate(rec["tool_calls"])]})
        rec["tool_results"] = []
        for i, c in enumerate(rec["tool_calls"]):
            key = (c["name"], c["arguments"])
            t0 = time.time()
            try:
                if key in seen: raise RuntimeError("repeated identical call blocked by harness")
                seen.add(key)
                fargs = json.loads(c["arguments"] or "{}")
                result = TOOLS[c["name"]](**fargs)
                ok = True
            except Exception as e:
                result, ok = f"ERROR: {e}", False
            out = result if isinstance(result, str) else json.dumps(result)
            print(f"   tool {c['name']}({c['arguments']}) -> {out[:120]!r}")
            rec["tool_results"].append({"name": c["name"], "arguments": c["arguments"], "ok": ok,
                                        "result": out, "ms": round((time.time() - t0) * 1000, 1)})
            messages.append({"role": "tool", "tool_call_id": c["id"] or f"call_{step}_{i}", "content": out})
    else:
        trace["stopped"] = "max steps"

    try:
        final_prompt = post("/apply-template", {"messages": messages, "tools": TOOL_SCHEMAS})["prompt"]
        trace["final_context"] = {"prompt": final_prompt, "n_tokens": len(tokenize(final_prompt, True))}
    except Exception as e:
        trace["final_context"] = {"error": str(e)}
    trace["messages"] = messages
    trace["total_s"] = round(time.time() - start, 1)
    with open(OUT, "w") as f:
        json.dump(trace, f, ensure_ascii=False, indent=1)
    print(f"\nStopped: {trace.get('stopped')}  |  Answer: {trace.get('final_answer')!r}")
    print(f"Trace written to {OUT}")

if __name__ == "__main__":
    main()


      

    


    
    

      
09Failure modes you'll meet

      

        
Runaway loops
Nothing in the model decides when to stop calling tools. On the Hacker News thread, one user's session ran over 180 tool calls in three hours. The harness caps turns, tokens per turn and wall-clock time, and blocks identical repeated calls.

        
Thinking eats the budget
Reasoning tokens are decoded at the same speed as answer tokens. At single-digit tokens per second, 2,000 thinking tokens means minutes before the first visible word. Check how much of each turn above was purple.

        
Malformed calls
At 2-bit quantization the model is more likely to emit invalid JSON or call syntax the parser doesn't recognise. The call then arrives as plain content, or json.loads fails. Return the error to the model as a tool result so it can retry, instead of crashing.

        
Context growth
Every tool result is appended forever. A 4 KB file read adds about 1,000 tokens to every later turn. Real agents truncate tool output, summarise old turns, or drop them. Compare the first prompt size with the final context size in the stats at the top.

        
Tool safety
The model chooses the arguments, so treat them as untrusted input. The harness resolves paths and refuses anything outside the project folder, and its calculator parses an AST rather than calling eval.

        
Sampling variance
At temperature 1.0, two runs of the same task differ. Reliable agents come from evals across many runs, not one good transcript. Run the harness a few times and load each trace here to compare.
